# Assistant (local): ask about your session, your screen, and let it learn

- Settings page gains an "Assistant (local)" group: point it at an OpenAI-compatible server (LM Studio and the like) on this machine or your local network, test the connection, then "Explain my session", ask a question, or "Ask about my screen" (one frame of the game canvas is sent with the question).
- "Suggest settings" reviews the measured session, the journal and the current settings, then proposes at most three adjustments — a closed list of actions (hunt radius, potion thresholds, monster classes on/off) with values clamped into safe bands, each with its measured reason. Apply one by one; Undo restores everything the assistant changed. No action outside the list exists, so nothing irreversible is reachable.
- "Learn from this session" distils the measured session into a small per-character journal (rewritten, never appended; contradictions replaced; measured facts only). The journal is saved with your settings and used when answering later questions. "Learn when hunting stops" does it automatically at the end of every hunt.
- Public internet addresses are refused before any request; only this machine or the local network may serve the assistant. Only the redacted snapshot the bug report uses is sent (no names, chat or locations); leave the model empty to use the first one your server lists.
- Off unless you configure it: an empty endpoint changes nothing, a failure or timeout only shows a message, and the bot never waits on the assistant.
- Also ships the local LLM tooling for developers (tools/llm: bench, diagnostics eval, journal distiller) and opens upstream PR #97 for the endpoint groundwork.

> Fork-only layer (upstream PR #97 covers the endpoint groundwork). Tested in simulation (726 integration tests with a stubbed server) and with live requests against the developer's LM Studio for the tooling and the journal contract — not exercised inside a live game session yet.
